## Why

The warehouse management page (`ProductionWarehouse`) has three defects: warehouse receipt/issue slips cannot be edited or deleted (missing across all three layers), the overview cards show wrong data due to a response-shape mismatch, and there is no month/year filter. Because each slip already mutated live stock (`lotProduct.soLuong`) and stored before/after snapshots, adding edit/delete safely requires transactional stock reversal — not a trivial CRUD addition.

## What Changes

- Add `update` and `delete` for warehouse receipts and warehouse issues across service, controller, and route layers. All stock mutations run inside `prisma.$transaction`.
- On delete, reverse the original stock impact (receipt → subtract back, issue → add back). On update, reverse the old impact on the old `lotProduct`, then apply the new impact on the (possibly different) `lotProduct`; recompute denormalized `tenKho`/`tenLo`/`tenSanPham`/`donViTinh` and `soLuongTruoc`/`soLuongSau` from current stock.
- Guard against negative stock: any operation that would drive `lotProduct.soLuong` below zero throws `ValidationError` and rolls back.
- Lock "special" slips: slips linked to a supply request, and issues auto-generated by a `MaterialEvaluation`, cannot be edited or deleted from the warehouse tabs (throw `ConflictError`). `getAll` returns an `isLocked` flag so the UI hides edit/delete for them.
- Add `PUT /:id` and `DELETE /:id` routes for both resources, restricted to `ADMIN`, `DEPARTMENT_HEAD`, `TEAM_LEAD` (same as create).
- Frontend: add update/delete service methods + `isLocked` typing; add Edit and Delete buttons to both tabs (hidden when `isLocked`); Edit reuses the create modal in edit mode; Delete confirms then refreshes lists and warehouses.
- Fix the overview cards: correct the response-shape access (`res.data.data`) for receipts/issues/supply requests, and add a "distinct in-stock items" count (`lotProduct.soLuong > 0`) to the stock card. No cross-unit quantity summing.
- Add month/year selectors at the page level (default "All"), filtering client-side. Applies to the receipt/issue count cards (by `ngayNhap`/`ngayXuat`) and to both tab tables (passed down via props).

## Capabilities

### New Capabilities
- `warehouse-slip-management`: CRUD lifecycle for warehouse receipt and issue slips, including transactional stock reversal on edit/delete, negative-stock guard, and locking of supply-request-linked and material-evaluation-generated slips.
- `warehouse-overview-dashboard`: The ProductionWarehouse overview cards and month/year period filter — correct data aggregation, distinct in-stock item count, and period-scoped receipt/issue counts shared with the tab tables.

## Impact

- **Backend**: `services/warehouseReceiptService.ts`, `services/warehouseIssueService.ts` (add update/delete + `isLocked` in getAll); `controllers/warehouseReceiptController.ts`, `controllers/warehouseIssueController.ts` (add update/delete handlers); `routes/warehouseReceiptRoutes.ts`, `routes/warehouseIssueRoutes.ts` (add PUT/DELETE); verify `routes/index.ts` ROUTE_MAP.
- **Frontend**: `services/warehouseReceiptService.ts`, `services/warehouseIssueService.ts` (update/delete + `isLocked`); `components/WarehouseReceiptTab.tsx`, `components/WarehouseIssueTab.tsx` (edit/delete UI + edit-mode modal + date-filter props); `pages/production/ProductionWarehouse.tsx` (card shape fix, in-stock count card, month/year selectors, pass period to tabs).
- **Data integrity**: Stock reversal touches `lotProduct.soLuong`; must be transactional and negative-guarded. References existing refund pattern in `services/materialEvaluationService.ts`.
- **Out of scope**: No server-side pagination for getAll; no Prisma schema change; no change to slip creation from MaterialEvaluation/SupplyRequest flows (only locking edit/delete from warehouse tabs); no cross-unit quantity aggregation.
